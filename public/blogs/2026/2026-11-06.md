Participated in a Hacktoberfest hackathon last week. 

It was my first time joining one, yet "super cooked", and learned something.

!["Lovely_Hackathon_Team"](/website/blogs/2026/2026-11-06-01.jpeg)

**1. AI tools are not always plug and play.**

We were supposed to work with open-weight LLMs, including Google Gemma. However, getting OpenCode to work with the model wasn't straightforward. We ran into API compatibility issues and quota errors before we could even get started.

**2. Faster code generation doesn't mean faster development.**

We had only four hours to understand the problem statement, work out a solution, build a POC, and record a demo video. It was a rush.

During development, there were moments when OpenCode modified existing code in ways we didn't intend. Some changes didn't fulfil the requirements, while others left the application unable to run.

AI helped us generate code, but we still had to review, debug, and verify what it produced.

**3. Documentation matters, even for a POC.**

Our README was largely AI-generated and hadn't been properly tested. What looked like sufficient documentation at first turned out to be difficult for beginners and judges to follow when setting up the project.

Documentation should be tested just like code.

**4. A working POC isn't necessarily a complete solution.**

Our original idea was to build a Tinder-like matching platform connecting investors with startups.

During the initial design, we envisioned two matching approaches:

- **Rule-based matching:** A weighted scoring system based on predefined roles and criteria.
- **LLM-based matching:** Allow users to select their matching criteria from the frontend, then pass those criteria together with the relevant payload to a third-party LLM to evaluate and determine the matches.

Ideally, users could switch between these two approaches.

Unfortunately, due to the time constraint, we only managed to implement the weighted scoring approach. The LLM-based matching mode never made it into the POC. It's a shame because that was one of the features we were most interested in exploring.

We also had to leave out several essential components:
- No proper database integration.
- No S3 integration for image storage.
- No authentication system.
- A relatively simple frontend and backend.

There was a clear difference between what we initially envisioned and what we managed to deliver within four hours.

**5. I didn't know what I didn't know.**

Perhaps one of my biggest takeaways was realising that I didn't really know how to use AI coding tools effectively.

Should we configure custom agents? Add `AGENTS.md` or `SKILL.md` files? Define specific instructions, workflows, or responsibilities for different agents?

I knew these concepts existed, but I wasn't sure when to use them, how to configure them, or whether they would actually improve our development workflow.

It made me realise that effective AI-assisted development is another skill to learn. Knowing how to write prompts is only one small part of it.

**Final thoughts**

Four hours. A lot of code. Plenty of debugging. And a fair amount of chaos.

I came away with a better appreciation of something: AI can accelerate development, but understanding the problem, making sound technical decisions, reviewing generated code, and validating the final product are still our responsibilities.

There's still a lot I don't know, and that's probably the most valuable thing I discovered.
